# 0015. Точное заявление страницы о принадлежности

Дата: 15.11.2026. Статус: принято.

В UI03 страницы посредников были ошибочно представлены как страницы оператора. Сравнение сохранённых чтений с повторным DNS-pinned чтением установило две причины: заявление о дилерстве присутствовало в первых12000 символах, но терялось при выборе пяти ценовых цитат; другой дисклеймер находился в конце уже полученной страницы за пределом12000 символов. Название бренда и поисковая подпись не подтверждают принадлежность сайта.

HTTP-граница остаётся1MiB. Reader нормализует этот же полученный снимок, сохраняет обычный префикс12000 символов и может дополнительно вернуть один непрерывный точный фрагмент до500 символов с явным заявлением о посредничестве или принадлежности. Ограниченный набор RU/EN-формулировок отдаёт приоритет прямому отрицанию официального статуса, затем самоназванию дилером/реселлером, затем партнёрскому соглашению. Названия компаний и домены не зашиты. Отсутствие такой формулировки не доказывает официальный статус.

`ReadPage.contentHash` новых чтений покрывает полный нормализованный полученный снимок. `text` остаётся его префиксом, `normalizedLength` — полной длиной; `provenanceExcerpts` содержит точные `text/start/end` в том же снимке. Строки не склеиваются. Старые источники, их хеши и цитаты не переписываются. Для фрагмента внутри префикса `pageEvidence` дополнительно проверяет буквальное совпадение и границы; фрагмент за префиксом создаёт только reader, получивший исходную страницу.

Каталог по-прежнему содержит максимум пять цитат до500 символов каждая. Одна позиция резервируется для найденного заявления; остальные отбираются прежним ценовым ранжированием, совпадения не дублируются. Ограничения явно сообщают о дополнительном чтении фрагмента за префиксом и возможной неполноте ценового каталога. При недостатке условий ответ должен оставаться частичным. Сам фрагмент — данные страницы, не серверная классификация и не новая инструкция. Prompt требует различать предложение самого оператора и предложение дилера; один партнёрский договор без достаточного контекста не устанавливает роль.

Проверки: два фактических нормализованных снимка UI03 с совпадающими префиксными хешами, точные offsets/full hash, сохранение ценовых цитат и5×500-границы, приоритет отрицания, отсутствие выдуманной роли, изменение только footer, corrupt offsets и передача обоих заявлений в настоящий generation input через обычный server-read pipeline. Живая смысловая проверка после изменения фиксируется отдельно.
