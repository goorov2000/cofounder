# ADR0022: сначала сведения, затем один итоговый ответ

Принято16.11.2026 по запросу пользователя снизить стоимость и задержку без потери полноты. Заменяет последовательность полных генераций и правило трёх непродуктивных циклов из ADR0021; остальные локальные, транспортные и финансовые границы сохраняются.

## Причина

Запрос `529e81f9-eec5-46ef-b03f-6d412e50e997` выполнил шесть полных генераций с последующей оценкой:434секунды/$1.458502801. При каждом замечании снова оплачивались большой контекст, ответ, память и независимая оценка. Интерфейс сохранял первый preview и скрывал поисковые фазы после появления текста, поэтому пользователь видел исчезающий статус и неизменный ответ.

## Решение

1. Luna выбирает действие answer/research. Текущая методика уже загружена; дополнительные пакеты нужны только для явно смежной задачи.
2. При research выполняются поиск и реальные чтения. Короткая Luna-проверка оценивает достаточность сведений по каноническим критериям, возвращая supported/unknown/missing и один прицельный запрос. Здесь нет полного ответа, памяти или авторских баллов.
3. Пробелы проверяются до написания ответа. Для конкурентов сначала ищутся прямые кандидаты, затем функции и официальные тарифы. Уже выполненная прицельная попытка позволяет оставить честное неизвестное. Полное доказательство уникальности не требуется.
4. Точный повтор query блокируется до оплаты; повтор широкого критерия сам по себе не останавливает разные полезные вопросы. Остановка после трёх последовательных партий без новых прочитанных `(URL, contentHash)` и без улучшения критериев. Неудачный дополнительный поиск сохраняет предыдущие источники. Успешный поиск с уже прочитанными URL не считается неудачным платным вызовом; допускается другой вопрос в пределах защиты от отсутствия прогресса. Одинаковые URL читаются один раз за задачу.
5. Основная модель составляет один итоговый ответ. Сохраняется одна структурная repair только для известного завершённого невалидного результата. Незавершённый основной ответ не применяется и автоматически не повторяется.
6. Независимый оценщик проверяет этот результат один раз; сохраняется прежняя одна repair невалидной завершённой оценки. Его замечание research больше не запускает очередную полную перепись. Оставшийся содержательный пробел показывается как partial.

Обычная локальная конфигурация сохраняет Sol для автора и оценщика. Luna используется для планирования, поиска и коротких проверок. Эксперименты с Luna-автором не прошли проверку полноты; переводить на неё основной ответ ради цены нельзя без дополнительных свидетельств. Программная настройка основной модели по-прежнему доступна.

Короткий planner получает1024токена, предварительная проверка1536, поиск2048, оценщик4096. Основной ответ без черновика получает до6144; intent=draft или переданный полный currentDraft сохраняет настроенный запас по умолчанию16384. Явный меньший AI_MAX_OUTPUT_TOKENS соблюдается во всех случаях; абсолютный максимум32768. Это потолки, а не целевой объём; max_output_tokens включает рассуждения, служебный JSON и видимый текст. Полный критический входной контекст не обрезается, повтор полного ответа в artifactDraft для обычного сообщения больше не требуется.

Живой эксперимент выявил несколько JSON вместо одного и незавершённый короткий план. Для этих **известных оплаченных** исходов разрешено ровно одно короткое исправление на Sol с прежней схемой. Несколько объектов не выбираются эвристически. Отказ, сеть, неизвестный usage или неопределённый расход не повторяются. Повтор короткой проверки не является повтором всей цепочки и отдельно учитывается в ledger с фактической моделью и тарифом.

Общий срок задачи15минут, timeout одного вызова180секунд, deadline оценщика до60секунд; это защита зависания, а не нормальное время ожидания. Общий разрешённый потолок$15 и прежний ledger не изменены. Перед каждым шагом — атомарный резерв; неизвестный расход сохраняет его. Фактическое списание учитывает подтверждённые cached input tokens по встроенному тарифу известной модели, а также сохраняет cached/reasoning usage для анализа. Пользовательские нестандартные тарифы не получают предположительную скидку.

В интерфейсе все реальные фазы видны до и после появления текста; рядом — прошедшее время. Таймер не озвучивается каждую секунду скринридером. Процент выполнения и оставшееся время не выдумываются.

## Проверка

Отчёт с успешными и неуспешными испытаниями (локальный материал). Контрольное живое исследование:одна генерация, два поиска,101секунда/$0.143541401,4/4 по отдельному оценщику. Это один ограниченный сценарий, не гарантия времени/цены/семантического качества для всех тем.

Последующий реальный пользовательский запрос остался2/4 из-за ошибочного сравнения broad focus, HTML-предела и отбора цитат. Пункт4 исправлен; HTML увеличен с1до4MiB при прежних12000символах текста/5×500цитат. Приоритет содержательных фрагментов справочных статей добавлен без снижения приоритета цен и без расширения каталога. Разбор и границы повторной проверки (локальный материал).
