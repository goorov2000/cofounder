# 0016. Ссылки через точный каталог источников

Дата: 15.11.2026. Статус: принято.

В affected11 модель дважды переписала `https://plan-smen.ru/pricing/` без завершающего `/`. Сокращённый адрес отсутствовал в запросе, поисковой выдаче и прочитанном каталоге. Отклонение было правильным; считать эти два адреса одинаковыми без основания нельзя.

Модель теперь может написать простую ссылку `понятная подпись (локальный материал)` в `message` или `artifactDraft.body`. Сервер проецирует только её destination в точный URL из существующего неизменяемого каталога этого запроса, привязанного к ID и версии свидетельства. Явные URL по-прежнему проходят обычную проверку: ошибочный путь или пропущенный символ не исправляются. Подпись, числа, валюты, текст claims, quoteId и версии не переписываются. Неизвестный alias, суффикс, fragment/query, вложенная подпись и изображение вместо простой ссылки отклоняются.

Это ограниченная Markdown-грамматика. Код, обычный текст и точные процитированные пользовательские реплики остаются данными. Последние распознаются только по буквальному совпадению с доступным снимком пользователя; исторические источники добавляются после проекции. Вложенные evidence/quotes/historySources не изменяются. Существующий UI не делает относительный `source_N` активной ссылкой. Ссылка на недоступную страницу не превращает её в прочитанное основание. Полный прежний read показывается в Sources, когда он указан структурированным claim/операцией; самостоятельная историческая ссылка без такого утверждения остаётся обычной ссылкой и не расширяет этот каталог автоматически.

Проекция проверяет суммарный положительный рост JSON обоих текстовых полей до сборки строки и сохраняет финальный предел512KiB после серверного обогащения. Сырые модельные ответы и rejectedOutput в repair остаются исходными. В финальном ответе и cache хранится канонический URL. Metadata отмечает citationAliasProtocol1; существующие budget/reserve/usage и единственная ограниченная repair не меняются.

Поток удерживает незавершённую ссылку или ещё не классифицированную цитату, продолжая выдавать остальную прозу. Полная корректная ссылка появляется сразу с настоящим URL. Ошибка preview прекращает только preview; финальная проверка и существующая repair продолжаются, без неучтённого повтора. Ошибка неизвестного alias не превращается в сетевой сбой или неопределённый расход.

Проверки: фактический slashless-отказ и repair через точный alias, неизменность claims, версии/изоляция/immutable-каталог, malformed/code/user-quote случаи, активные ссылки на каждом префиксе потока, byte expansion, два текстовых поля, metadata/usage/reset и сохранение исходного raw. Протокол ссылок не доказывает смысловую правильность подписи или вывода; живая смысловая приёмка выполняется отдельно.
