# ADR0020 — исполнение следующего действия оценщика

16.11.2026. Пользователь сообщил, что после восстановления источников бот дополнил сравнение, но опять остановился на следующей проверке. Оценщик уже отмечал невыполненную доступную работу; сервер сохранял замечание, не исполняя его.

## Решение

Оценщик возвращает машинное `nextStep`: research / ask_user / complete / blocked / null, отдельно от пояснения `nextAction`. Старые проверки читаются без поля; новые live-проверки требуют его в строгой схеме. Автор ответа не управляет этим решением.

`runResearchLoop` исполняет research в том же HTTP-запросе: прицельный план, поиск, чтение, новый ответ и независимая оценка. Уточнение после записи пользователя16.11: HTTP сохраняет первый потоковый preview на экране, а после внутреннего onTextReset перестаёт передавать новые черновики. Статусы показывают реальный ход работы; только проверенный complete заменяет текст окончательным ответом. SSE text.reset больше не отправляется обычным сервером, клиент поддерживает прежний протокол. Исходная пользовательская реплика и версии памяти прежние; вымышленные пользовательские сообщения не создаются. В память атомарно попадает только окончательный ответ. Полные промежуточные message/artifactDraft передаются следующему шагу как предложения AI, не факты пользователя.

Если нужен личный выбор, но вопрос ещё не сформулирован, отдельный answer-шаг задаёт конкретный вопрос. Готовый вопрос передаёт управление пользователю. Остановка, запрет нового поиска и ограниченный вопрос о статусе не превращаются в дополнительные исследования. Точное ключевое слово для продолжения не требуется.

## Пределы и ошибки

- Не более трёх последовательных циклов на запрос. Резервирования поэтапные, в прежнем ledger и общем потолке $15. Полный консервативный admission учитывает все циклы, рост контекста и исправление оценщика.
- Один цикл сохраняет предел до120секунд. Последовательность получает до360секунд; crash/pendingUntil, HTTP deadline и раннее сохранение частичного ответа согласованы. Пределы страниц, результатов поиска и модельных выходов сохраняются.
- Операции и чтения имеют имена research-N:..., usage/стоимость суммируются за запрос. HTTP проверяет выход по действительно начатым операциям; ограниченный trace допускает64операции для всех циклов/исправлений. Повтор requestId возвращает сохранённый итог без новых вызовов.
- Повтор query блокируется до второго поиска. Неопределённая сетевая ошибка поиска автоматически не повторяется.
- Завершённый невалидный ответ оценщика получает одно бюджетируемое исправление структуры/согласованности. Сеть, отмена, timeout и неопределённый исход не повторяются. Повторно неверная оценка остаётся unavailable; безопасные path/rule сохраняются, оценки не повышаются ради схемы.
- При нехватке бюджета, сбое, исчерпании времени или числа циклов возвращаются последний проверенный ответ, реальные страницы и конкретное ограничение. Пробелы не закрываются ради выхода. Недоступность оценщика после исследования также сообщается явно.
- Два URL могут перенаправиться на одну страницу. Идентичность нового read включает operationId; два фактических чтения не конфликтуют в каталоге. Старые IDs не переписываются.

Уточнены остановка после восстановления из ADR0019 и однократная оценка прежней реализации. Восстановленный ответ может стать промежуточным; доступная следующая проверка исполняется автоматически. Бюджеты, доверие источникам и атомарность сохраняются.
