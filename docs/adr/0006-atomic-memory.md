# ADR 0006 — Версии решений и точные исходные сообщения

15.11.2026. Статус: реализовано для клиентского состояния и совместимых API-схем; извлечение операций моделью подключается отдельно провайдером.

Workspace сохраняет version=1. Project.core — совместимое необязательное поле на входе. Старые requests и cached replies читаются без добавления defaults: тело прежнего запроса и его финансовая идентичность не изменяются. Новое пользовательское действие создаёт contractVersion=2 и coreContext. Краткая ChatMemory остаётся обзором, её предел шесть фактов не ограничивает атомарные требования.

Атомарная запись имеет стабильный ID, key, scope и историю версий. Origin, epistemic и acceptance независимы: принятая цена остаётся гипотезой. Предложение не заменяет принятое решение; изменение области или внешнего тарифа требует отдельной записи. getCurrentEntries определяет последние версии. В запрос передаются все версии entries, currentEntryRefs явно указывает текущие; sourceMessages содержит точные тексты и редакции, включая вышедшие за последние 40 реплик. Эти массивы не обрезаются по размеру. После reset старые сторонние разговоры исключаются из нового контекста по существующему allowsChatContext; полный архив остаётся в проекте. История всех включённых линий и необходимые ей источники передаются целиком. Методы/поиск не заменяют прямой контекст.

Модель предлагает только memoryOperations. Сервер формирует identity/base envelope из запроса. applyMemoryPatch повторно проверяет структуру, project/module/generation, ожидаемые memory/context versions, точную редакцию, роль автора, цитату, зависимости и переходы статусов. Дубликат requestId идемпотентен. Патч целиком проверяется до появления нового состояния. AI-источник не даёт пользовательского принятия; observed требует прочитанного внешнего фрагмента. URL или search snippet сами по себе этого статуса не дают. Числа без основания отклоняются консервативно.

Это проверка происхождения, а не доказательство смысла или истинности. Наличие цитаты не доказывает полномочия директора, отрицание, эквивалентность единиц или существование интервью. Эти контрпримеры остаются отдельными размеченными/model-evaluation сценариями C03/C04. Автотесты патчей не заменяют независимую оценку извлечения.

Обычный submit архивирует точное сообщение до отправки. Reply, patch, summary и proposal применяются единым applyAnswer только после валидного complete. Partial, ошибка и отказ не коммитятся. Regenerate получает актуальную память, сохраняя историческую разговорную часть. Правка исходного сообщения предлагается в request snapshot; старые сообщение/ответ остаются до успеха. Успех архивирует обе редакции, помечает прежние производные решения unresolved и зависимые результаты stale; принятие более позднего решения нельзя отменить пересчётом раннего хода. Reset повышает generation и удаляет только lineage выбранного разговора, оставляя зависимые результаты с причиной пересмотра. Переключение проектов сохраняет адресата запроса. Web Locks и сравнение persisted bytes защищают от перезаписи другой вкладки.

Новые сохранённые материалы фиксируют basedOn с использованными версиями атомов и свидетельств. Материалы без точных зависимостей инвалидируются консервативно по связанным этапам. Сохранённый текст остаётся, assessment очищается, числовые сценарии получают stale/reason. Добавленное существенное условие также требует пересмотра существующих материалов. Legacy facts хранятся, но актуальное принятое решение с тем же project-wide key исключает старое значение из активного facts-контекста.

Миграция детерминированна: реальные Fact становятся legacy/unresolved, проверенность не повышается, существующие тексты сообщений архивируются только под реальными ID. ChatMemory не превращается в выдуманные атомы. Перед первой записью core исходные bytes копируются в cofounder.workspace.v1.pre-core под прежним storage lock. Если резерв/проверка/запись не удаётся, прежняя durable запись остаётся. Резерв доступен после reload. При импорте owned project refs в core/replies меняются; финансовые request snapshots остаются точными, pending/failed requests получают IMPORTED_REQUEST и не имеют кнопки повторного выполнения. Новое исследование/сообщение требует явного действия.

Пределы: workspace 4 000 000 UTF-8 bytes; каждый HTTP send, retry, edit и regenerate — 128 KiB. Ошибка явно указывает экспорт JSON и продолжение в копии/сокращение необязательных материалов. Нет скрытого удаления требований. Quota оставляет текущую работу в памяти и предыдущую persisted версию; кнопки экспорта/восстановления уже доступны в разделе проектов.

Проверки: tests/domain/core-memory.test.ts, storage.test.tsx, restart.test.ts; tests/workspace/answerRequests.test.ts, api-stream.test.ts, screen.test.tsx; tests/e2e/core-memory.spec.ts плюс существующие streaming/restart/edit/regenerate сценарии. Все автоматические прогоны с пустым OPENAI_API_KEY и AI_BUDGET_USD=0. Browser mock доказывает путь применения и сохранность, не качество живого извлечения.
