# ADR0008 — источники, поток и воспроизводимая приёмка

15.11.2026. Первая сборка логики; ограничения живой приёмки перечисляются в `docs/bot-core-acceptance.md`.

UI расширяет существующий разговор и действие «Посмотреть источники». Никаких отдельных форм решений, задач или новых панелей нет. Пока приходит `progress`, отображается его проверенный русский статус; после первого `text.delta` — поток текста. Progress принадлежит тому же requestId/project/module, сброс/отмена отсекают позднее событие. Исходный черновик очищается при отправке, новый ввод сохраняется. Неполный поток и transport error не применяют память; проверенный полный ответ с partial research может сохранить явно ограниченные источники.

Список источников строится по `externalSources` из проверенного ответа сервера, а не по ссылкам в prose. Он показывает read/snippet/unavailable, точный фрагмент, даты/версию, ограничения и единицы/оплату `externalClaims`. Слова пользователя, legacy и методики имеют отдельные подписи. `verified` не меняет смысл. Partial/failed research получает видимую пометку и путь отдельного нового исследования. При budget exhaustion сохранённая работа/ручное редактирование/экспорт доступны.

Полный JSON переносит память и источники; import remaps project refs, но не создаёт новый paid retry из исторического snapshot. Markdown дополнен историей атомов, точными репликами, свидетельствами, claims, состоянием исследований и зависимостями сохранённых итогов. Старые поля остаются читаемыми.

Лимит клиентского ответа вырос с100k символов до1MB UTF-8 на JSON/frame и2MB на поток: один ответ включает6 методик и6 источников. Это не увеличение HTTP request128KiB. Валидаторы продолжают работать после транспорта. Обнаруженный допустимый максимум6×12000 кириллических символов даёт147130B server envelope, отвергаемый прежним80k guard; следующий контекст160946B явно блокируется. Это воспроизводимый конфликт лимитов для общего ремонта, а не доказательство причины любых прошлых ошибок. Ничего не обрезается молча.

Runner сохраняет все46 исходных записей полностью и17 next_build. `deterministic` проверяет готовность setup/схемы, не семантику. Live выполняется только с `--live`, существующей моделью/ключом/ledger/cap<=5, дополнительным расходным ограничением; не создаёт новый финансовый журнал. `mock_tool --live` подменяет только внешний каталог/reader, планировщик и итог генерирует реальная модель. `browser` использует реальный UI и API, отдельные порты/профиль. Программный DI не доступен через публичный запрос. Сохраняются входы/выходы/расход/ошибки и версии, без секретов и скрытых рассуждений.

HTTP200, зелёные mock-тесты и заполненность разделов не заменяют независимую разметку expected/forbidden. C15 разделяет процесс и результат без среднего процента. Полный оценщик, остальные17 исходных случаев, методическая приёмка остальных этапов и финальный бриф остаются следующей сборке. R30–R33 родительского брифа целиком не объявлены закрытыми; публикации/домена в этой поставке нет.
