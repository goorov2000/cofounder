# Правила реализации интерфейса для агента

17.11.2026 — таблицы Markdown сохраняют нативный `display:table` и заполняют рамку; прокручивается только `.markdown-table`. Не возвращать `display:block` на таблицу или запрет переноса всего текста. Обёртка имеет стабильный тип компонента, чтобы сохранять горизонтальную прокрутку при наборе сообщения. Пример «Таблица в ответе» — `/design-system`; проверка (локальный материал).

17.11.2026 — «Расчёт» рынка/экономики использует общий `CalculationWorkbench`: результаты сверху, компактные вводные с происхождением, основания и формулы раскрываются. Новые ответы наставника автоматически переносят числовые входы с буквальными цитатами; гипотезы не подтверждаются автоматически. Ручные значения защищены от перезаписи. Пустые поля неизвестны, счётчик «Заполнено» не означает готовность этапа. Пример — `/design-system`; проверка (локальный материал).

17.11.2026 — по последнему уточнению вопросы с посильным выбором по умолчанию получают2–4кнопки `AnswerChoices`, в том числе о бюджете/времени, географии, формате и канале; свободное поле сохраняется. Если автор оставил такой вопрос открытым, независимый проверяющий может дополнить варианты без повторной генерации. Для прошлого случая или действительно нужного точного ввода допустим свободный ответ. В проработке рынка определения, формулы с неизвестными и пример одного SOM остаются «Частично»; «Расчёт TAM/SAM/SOM» закрывается по численным результатам всех трёх уровней с основаниями. Старое преждевременное покрытие корректируется при отображении, история сохраняется.

17.11.2026 — при недоступном наставнику личном факте/решении следующий шаг — один конкретный вопрос, без «можем продолжить, если хочешь». Готовый вопрос `ask_user` независимого проверяющего может дополнять ответ автора, если вопроса/кнопок нет; исходная оценка при этом не повышается. При истинной ошибке сохранения предупреждение остаётся в общей оболочке, не дублируется над чатом. Полученный ответ продолжает быть доступен в памяти и экспорте даже при отказе физической записи. Проверка (локальный материал).

17.11.2026 — недоступные внешние страницы пропускаются; журнал ошибок чтения и блок «Исследование не завершено» не выводятся в переписке. Технические подробности доступны по запросу через «Ещё действия с ответом» → «Посмотреть источники». Существенный пробел в данных помощник кратко объясняет в самом ответе как неизвестный бизнес-параметр. Правило действует и для сохранённых старых ответов.

17.11.2026 — при возврате к уже обсуждённой теме сохранённая проработка остаётся видимой даже после изменения общего контекста другими этапами. До нового ответа показывать статусы и пояснения как предыдущую оценку с явной подписью; её следующий пункт тоже относится к прошлой оценке. Она не означает актуальную готовность и не открывает новые этапы. После обрыва запроса снимается ожидание, но остаётся подписанная сохранённая оценка. «Ещё не оценено» — только при отсутствии подходящей сохранённой оценки; перезапуск чата по-прежнему очищает её. Проверка (локальный материал).

Логотип16.11.2026: использовать общий BrandMark с прозрачным оригиналом пользователя, не Sprout и не другую библиотечную иконку. Рисунок не перерисовывать. По последнему уточнению пользователя никакого скруглённого квадрата или заливки вокруг: самостоятельный знак32px в меню,28px в галерее, currentColor=--ds-accent. Favicon тоже прозрачный, с двумя цветовыми вариантами палитры для светлого/тёмного браузера. Правила и воспроизводимость — brand.md. Учитывать все палитры, свёрнутое меню и мобильную навигацию.

Последнее уточнение16.11.2026: выбор палитры — компактная немодальная панель248px у кнопки (native popover), без затемнения, inert/focus trap и блокировки чата. Варианты доступны одновременно, нажатие сразу применяет палитру, список остаётся открытым для сравнения. Повторное нажатие, внешний клик, Escape, крестик и выход фокуса за панель закрывают её. Для этой настройки не использовать Modal и не вводить циклический перебор. Ограничивать координаты и размер окном браузера; на телефоне панель под кнопкой, на desktop рядом с меню. Действует и в /design-system. Подробности — palette-popover-validation.md.

Уточнение16.11.2026 — цветовая палитра выбирается пользователем независимо от светлого/тёмного режима. Пять вариантов с русскими названиями: Сбер (зелёная адаптация SDDS Service), СберБизнес (прежняя бирюзовая), Плазма (синяя адаптация Plasma Web), Гига (графитовая адаптация Plasma Giga), Ирис (собственная фиолетовая). По последнему уточнению и скриншотам СберБанк Онлайн основа всех палитр общая и нейтральная: фон, поверхности, обычный текст, рамки, hover/active и disabled не окрашивать акцентом. Цвет только у бренда, действий, ссылок, выделения и фокуса; статусы сохраняют семантические цвета. Это заменяет обязательность одной палитры СберБизнеса. Использовать общие PaletteControl/PalettePicker и useTheme; цвета только в tokens.css, названия/ID — palettes.ts. Геометрия, шрифты и поведение общие. Новые компоненты проверять во всех десяти сочетаниях, не возвращать жёстко заданный бирюзовый. Источники, контрастные адаптации и хранение — README; актуальная проверка — neutral-palettes-validation.md. Кнопка светлого/тёмного режима по-прежнему переключает его сразу без диалога.

Уточнение пользователя16.11.2026: точка подключения AI в шапке чата бесполезна и убрана. Не возвращать постоянный визуальный индикатор; проверка подключения и доступный статус для скринридера сохраняются.

Уточнение пользователя16.11.2026: начальный экран этапа открывает маршрут; после начала разговора анимированно открывается «Проработка темы». Общие правила движения обязательны: [motion.md](motion.md), токены в tokens.css, `Disclosure` для раскрытия и `animateMotion` для Web Animations. Не задавать локальные длительности/easing. После первой отправки не перебивать ручной выбор раздела новыми ответами. Учитывать reduced motion, в том числе его включение во время движения; скрытый раздел сразу inert/aria-hidden. Это заменяет постоянное начальное раскрытие маршрута в уже начатом чате. Пример — `/design-system#motion`.

Последнее уточнение пользователя16.11.2026: первый экран каждого этапа — название прописными буквами в центре чата и краткое справочное описание мелким шрифтом. До начала диалога название в шапке отсутствует; после первой отправки оно анимированно перемещается туда. Использовать `StageIntro` и `useStageTitleTransition`, учитывать reduced motion. «Начать с сохранённого» заменено понятным «Начать этап», контекст учитывается автоматически. Пример — `/design-system`; детали — начало README. Это заменяет старое правило постоянного названия в шапке пустого чата.

Этот документ — контракт CoFounder, принятый по запросу пользователя 14.11.2026 на дизайн-систему по референсам СберБизнеса, светлую и тёмную темы и исследование других продуктов Сбера.

1. Перед UI-изменениями прочитай [описание системы](README.md). Для происхождения решений — [исследование](sber-research.md). Открой `/design-system`; сверь изменяемый элемент с существующим примером.
2. Используй `src/design-system/tokens.css` и общие компоненты из `components.tsx`, существующие `Modal`/`IconButton`. Не создавай второй набор цветов или свой переключатель темы внутри фичи. Сначала ищи соответствующий компонент через `rg`.
3. Новое значение цвета вводится только в tokens.css, сразу для двух тем, с ролью и объяснением в README. В стилях фич запрещены новые literal hex/rgb/white/black. Исключение — данные исследовательских образцов, print и иконки/иллюстрации с собственным содержанием.
4. Цвета называются по назначению: text, surface, action, border, warning. Не назначай одному токену одновременно фон кнопки и цвет её подписи. Различай брендовый `--ds-brand` и контрастный `--ds-action`.
5. Выбирай размеры из шкалы, не добавляй новый радиус для каждого экрана. Панель 28, вложенная карточка 16, элемент 8 px. Левое меню и рабочая область — основные панели, обе используют радиус 28 px. Строки меню и «Проектов» — 48 px с промежутками 8 px и общей колонкой значков/подписей; сетка действует и в мобильной навигации. Допустимы существующие адаптивные значения; новое исключение объясни локально.
6. Уточнение 15.11.2026: чат и маршрут — единая поверхность, одна компактная строка этапа; поле сообщения ChatComposer с текстом, микрофоном и стрелкой на одной строке; под ответом постоянно видимый AssistantActions, под своим сообщением UserMessage с действиями при hover/focus (на touch видны), под вводом AIDisclaimer, подготовка и сохранение итога прямо в переписке через StageResult без отдельного окна (уточнение16.11.2026). Длинные списки причин блокировки этапов не выводить. Проекты и тема — в левом меню (тема на телефоне — в верхней строке). Уточнение пользователя того же дня: общая прокрутка чата и карточки проекта по внешнему правому краю, без отдельной полосы между ними. По последнему уточнению пользователя 16.11.2026 в компактной карточке ProjectPanel три раскрывающихся раздела одного уровня в порядке «Маршрут проекта», «Проработка темы», «Контекст проекта». Маршрут по умолчанию раскрыт, два остальных раздела свёрнуты. Одновременно раскрыт максимум один раздел: открытие любого закрывает остальные, повторное нажатие сворачивает открытый. В шапке остаются текущий этап и прогресс. Переключение не сбивает место чтения; отдельную полосу прокрутки панели не добавлять. Память обновляется с ответом AI и уточняется через чат; кнопки презентации в этой панели нет. Уточнение пользователя: «Итог этапа» и «Уточнить в чате» убраны из панели, пояснение об автоматическом обновлении скрыто в маленьких InfoHint рядом с «Проработкой темы» и «Контекстом проекта». В проработке — критерии и прогресс текущего этапа, в контексте — известные вводные и решения; отдельные блоки «Предположения» и «Осталось уточнить» убраны по уточнению16.11.2026. Прогресс считается по обсуждённым критериям, а не сообщениям или сохранению итога; старое состояние без оценки не получает выдуманный процент. Пояснение критерия раскрывается нажатием, цвет сопровождается текстом статуса. Без повторного названия этапа и служебного подвала. Карточка 320 px, на узком ноутбуке 280 px; без нового внутреннего скролла. Полный документ доступен из предложения в чате и через «Как работать» → «Открыть материал этапа»; расчёт — на соответствующих этапах; на узком экране панель открывается диалогом. Вкладки «Разговор»/«Итог» над чатом убраны. Повторное уточнение 15.11.2026: общая прокрутка до низа экрана, поле ввода закреплено только под разговором и не отнимает высоту у маршрута. Отдельные разделы «Решения проекта», «План доработки» и форма ключей/значений удалены; вводные и следующие действия обсуждаются в чате, сохранённые итоги служат контекстом этапов. Не возвращай отдельную анкету или панель задач в этот сценарий. Варианты ответа — общий AnswerChoices: компактный вертикальный список по всей ширине сообщения, в строке название и пояснение ниже, padding 8 px и минимальная высота кнопки 48 px. Между сообщениями 16 px; перед вводом один отступ 16 px без добавочного margin последнего сообщения. Отдельную кнопку «Свой вариант» не добавлять: свободный ответ и диктовка доступны в основном поле чата. Открытые вопросы могут быть без вариантов; не принуждать модель выдавать choices на каждый ход. Сохраняй главный сценарий: широкий центральный чат и компактное меню. Не превращай рабочий экран в рекламный лендинг, сетку статистики или набор равноправных карточек. Обучение открывается по запросу.
7. Не переноси градиентные подложки мобильного банка в длинный текст чата. Розничный мобильный экран — дополнительный референс группировки и жестов, а Triplex — первоначальная основа компонентов. Все действия рабочего экрана используют семантические цвета выбранной пользователем палитры.
8. Во время ожидания ответа показывай общий ThinkingIndicator: мягкая анимация и редкие нейтральные вариации «Думаю…», без выдуманных этапов, поиска или процентов. Скринридеру — одно стабильное сообщение; при reduced motion индикатор статичен. «Повторить тот же запрос» доступно только для восстановления после обрыва, не во время активного вызова. Предупреждение об ошибках AI расположено под полем ввода, с отступом 8 px; над полем — мягкая граница прокрутки.
9. Для нового элемента определи normal/hover/active/focus/disabled и содержательные состояния empty/loading/error/success, когда они существуют. Показывай понятный текст действия. Успех сохранения не означает подтверждение бизнес-гипотезы.
10. Используй настоящие button/input/select/dialog и связанные подписи. Иконка без текста имеет aria-label. Выбор имеет aria-pressed/checked/current. Не делай кликабельный div без полноценного клавиатурного контракта.
11. Фокус различим в обеих темах. Тема не меняет фокус, положение чтения, текущий этап, содержимое черновика или способ сохранения. Текст полей на телефоне не меньше 16 px. Учитывай reduced motion.
12. Новый компонент добавляется в библиотеку `/design-system` с интерактивным примером. Локальные данные примера вымышленные; реальные банковские сведения, фотографии контактов и счета не копировать.
13. Проверка перед сдачей: обе темы на desktop и mobile, клавиатура, переполнение и короткий ноутбук, затем относящиеся к изменению тесты. Использовать отдельный UI-сервер с неработающим API или mock, не отправлять живые AI-запросы ради проверки дизайна.

При необходимости подключить внешнюю библиотеку выбери одно семейство и проверь текущую версию, совместимость React и условия поставки. Открытый Triplex Next на дату исследования заявлял React 18, текущий прототип использует React 19. Поэтому пакет не установлен автоматически. Оригинальный код и SB Sans также не скопированы. Сведения о доступном SDDS MCP — в исследовании; настройка агента этим этапом не менялась.
