17.11.2026 — таблицы Markdown сохраняют нативный `display:table` и заполняют рамку; прокручивается только `.markdown-table`. Не возвращать `display:block` на таблицу или запрет переноса всего текста. Обёртка имеет стабильный тип компонента, чтобы сохранять горизонтальную прокрутку при наборе сообщения. Пример «Таблица в ответе» — `/design-system`; проверка (локальный материал).

17.11.2026 — «Расчёт» рынка/экономики использует общий `CalculationWorkbench`: результаты сверху, компактные вводные с происхождением, основания и формулы раскрываются. Новые ответы наставника автоматически переносят числовые входы с буквальными цитатами; гипотезы не подтверждаются автоматически. Ручные значения защищены от перезаписи. Пустые поля неизвестны, счётчик «Заполнено» не означает готовность этапа. Пример — `/design-system`; проверка (локальный материал).

## Где смотреть и что подключать

- [Живая библиотека](http://localhost:3000/design-system): обе темы, компоненты, интерактивный пример чата, сравнение открытых тем Сбера.
- [Мастерская](http://localhost:3000): кнопка солнца/луны внизу левого меню (на телефоне — в верхней строке) сразу переключает тему. Подсказка называет действие: «Включить тёмную/светлую тему».
- `src/design-system/tokens.css` — единственный источник новых цветов, размеров и типографики.
- `src/design-system/components.tsx`, `ChatComposer.tsx` и `components.css` — Button, Card, Field, Status, Alert, EmptyState, ChatComposer; классы таблицы, select и textarea.
- `src/design-system/product.css` — применение системы к существующим экранам и адаптивная компоновка.
- `src/design-system/theme.ts`, `ThemeControl.tsx` — выбор темы и синхронизация.
- `src/components/ui/Modal.tsx` — общий нативный диалог, используется и библиотекой, и приложением.
- `source-tokens.json` — вычисленные браузером переменные исходных HTML, без текста банковских данных.
- `research/theme-comparison.json` — значения открытых тем, ссылки и SHA файлов источников.
- [Правила для агента](agent-guide.md) — обязательная точка входа перед изменением UI.

Всё загружается локально из сборки. На странице библиотеки нет вызовов AI, банковских запросов или внешних шрифтов. Ссылки на документы открываются только по действию пользователя.

## Визуальная основа

Рабочая аудитория — начинающий предприниматель; основное действие — разговор о проекте. Нейтральный фон приложения отделяет крупные панели, внутри панели пространство разделяется отступами и редкими границами. Акцент выбранной палитры обозначает доступное действие и текущий шаг. Тени используются для диалогов; обычным панелям они не нужны.

Из скриншотов взяты крупные спокойные поверхности, контраст масштаба панели и компактного элемента, вторичный текст, линейные иконки, разделение данных на основную строку и пояснение. Из HTML взяты цветовые роли и состояния. Размеры под наш сценарий адаптированы: чат получает основную ширину, слева компактное меню, справа маршрут.

```text
┌──────┐  ┌──────────────────────────────────────────────────┐
│ Меню │  │ Этап                                    ?  ◧   │
│      │  │                               ┌─────────────┐  ▒│
│      │  │ Широкий разговор               │ Маршрут · ⌄ │  ▒│
│      │  │                               │ Проработка  │  ▒│
│      │  │                               │ Контекст    │  ▒│
│      │  │                               └─────────────┘  ▒│
│Папка │  │                                                ▒│
│      │  │                                                ▒│
│ Тема │  │ Сообщение               🎙 ↑                    │
└──────┘  └──────────────────────────────────────────────────┘
```

Чат и компактная карточка `ProjectPanel` находятся внутри одного scroll-контейнера: полоса прокрутки проходит справа от всей рабочей области. Вертикальной перегородки и отдельной прокрутки маршрута нет. Панель остаётся под рукой при чтении; раскрытая карточка большой высоты доступна через ту же общую прокрутку. Над перепиской — название этапа, помощь и переключатель панели. Проекты и тема находятся в левой навигации; статус подключения AI доступен скринридеру, постоянного визуального индикатора в шапке нет.

По последнему уточнению пользователя 16.11.2026 в карточке три раскрывающихся раздела одного уровня: «Маршрут проекта» с девятью шагами, «Проработка темы» с критериями и прогрессом, ниже — «Контекст проекта» с известными вводными и решениями. Маршрут раскрыт по умолчанию, два остальных раздела свёрнуты; открытие любого закрывает остальные, повторное нажатие закрывает открытый. Текущий этап и прогресс остаются в компактной шапке маршрута. Контекст и проработка обновляются после ответа AI. В панели нет «Итога этапа», «Уточнить в чате», презентации и постоянной подписи об обновлении. Пояснения доступны в маленьких подсказках у значков информации рядом с «Маршрутом проекта», «Проработкой темы» и «Контекстом проекта»: hover, фокус или нажатие, Escape и нажатие снаружи закрывают её. Подсказка не раскрывает список и не открывает диалог. На рынке/экономике остаётся расчёт. ## Компоненты и состояния

Уточнение16.11.2026 по диалогу о расписании ресторана: после полного покрытия темы главное действие — проверить формулировку и сохранить результат. `StageResult` показывает полный текст в общей переписке без отдельного окна, оранжевой подложки и вводной инструкции. Основной текст и заголовки разделов —14px, заголовок блока —16px. При полном актуальном покрытии без замечаний проверки — «Сохранить и продолжить»; дальнейшее обсуждение остаётся добровольным. Запись и переход происходят только после нажатия. При неполноте или замечаниях нельзя выдавать результат за готовый: сохраняется возможность явно записать рабочий текст. Ошибка/ожидание нового ответа блокирует сохранение предыдущего предложения. Ручное редактирование, прошлый сохранённый текст, проверка полноты и удаление доступны из этого же блока. Интерактивный пример — `/design-system`; проверка — stage-result-validation.md (локальный материал).

| Элемент | Контракт применения | Проверяемые состояния |
|---|---|---|
| `Button` | Одна основная кнопка на локальный сценарий; остальные secondary/ghost; danger для удаления | normal, hover, active, focus-visible, disabled, busy |
| `Field` | Постоянная подпись; hint объясняет формат; error связывается через `aria-describedby` | empty, filled, invalid, disabled, focused |
| `Card` | Одна смысловая область; заголовок и действие в общей шапке | Содержимое, пустое состояние |
| `Status` | Подпись и точка; success только для фактически выполненного действия | neutral, success, warning, danger, info |
| `Alert` | Конкретная причина и следующий шаг; не применять как постоянную декоративную плашку | success, warning, danger, info |
| `EmptyState` | Что здесь появится и с чего начать; одна кнопка при необходимости | Пустой список, отсутствие итога |
| `Modal` | Нативный dialog; короткий заголовок; явные действия | Escape, возврат фокуса, прокрутка длинного содержимого |
| Таблица | Текст слева, числа справа; вторичная строка под названием | overflow внутри контейнера, фильтр, статусы |
| Чат / `ChatComposer` | Ответ помощника на основной поверхности, собственное сообщение на нейтральной подложке; поле закреплено снизу | история, варианты ответа, draft, busy, error, диктовка; доступный label визуально скрыт |
| Варианты ответа / `AnswerChoices` | Вертикальные строки: номер, название, пояснение; один вопрос | normal/hover/active/focus/disabled; selected в примере; пустой список не отображается |
| Маршрут | Вертикальная последовательность; текущий / сохранённый / недоступный этап | Недоступность — замок и `aria-disabled`, без перечисления предыдущих этапов; текущий `aria-current` |

Общие `AssistantActions`, `UserMessage` и однострочный `ChatComposer` представлены в интерактивном примере `/design-system`.

Примеры `Alert` в галерее статичны и не объявляются скринридером как новые ошибки. В реальном асинхронном сценарии размещать изменяемое сообщение в appropriate `role="status"` или `role="alert"` по смыслу. `busy` у Button блокирует повторное действие и показывает подпись, анимация отключается при reduced motion.

```tsx
import { Button, Field, Card } from './design-system/components';

<Card title="Новый проект">
  <Field label="Название" value={name} onChange={e => setName(e.target.value)} />
  <Button variant="primary" onClick={save}>Создать проект</Button>
</Card>
```

Композиция формы задаёт расстояния между элементами. Новые компоненты используют семантические `--ds-*`; старые `--ink`, `--teal` и другие оставлены как переходные алиасы. Существующие экраны подключены через `product.css`; отправка использует общий ChatComposer и Button; подготовка итога доступна в диалоге «Результат этапа». Полная перепись всех JSX старого прототипа на новые обёртки не выполнялась.

## Адаптивность и тема

- Desktop и планшет от 640 px: меню раскрыто по умолчанию, ширина 200 px; кнопка сворачивает его до 76 px. Колонка карточки проекта 340 px, в узком desktop 300 px (включая отступ справа), внутри общей прокрутки с чатом. Переписка занимает всю оставшуюся ширину без прежнего предела 816 px. Область ввода отдельно ограничена 816 px с отступами и центрируется под разговором — решение пользователя 16.11.2026.
- До 900 px вся панель проекта открывается диалогом по кнопке рядом с названием этапа. До 640 px меню тоже открывается диалогом, внешние промежутки панелей убираются. Таблица прокручивается внутри своей области.
- Высота 720 px проверяется отдельно: нижние действия сообщения должны оставаться доступны.
- По умолчанию тема следует за системной настройкой. Кнопка одним нажатием включает противоположную тему: светлую или тёмную. Диалога и пункта «Как в системе» нет — решение пользователя 14.11.2026.
- Ручной выбор хранится в `cofounder.theme.v1` независимо от данных проектов и имеет приоритет над системой. Тема устанавливается в `<head>` до рендера React; изменения синхронизируются между вкладками. Без ручного выбора (включая ранее сохранённое `system`) приложение следует за системой.
- При недоступном localStorage выбор работает в памяти текущей страницы. Перезагрузка в этом случае может вернуть системную тему.
- Оформление меняет цвета и поверхности без смены маршрута, очистки черновика или отправки сообщения. Для печати задана светлая базовая палитра.
