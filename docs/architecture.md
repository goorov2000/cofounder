# Архитектура CoFounder

React/TypeScript SPA — рабочее пространство одного браузера без регистрации. Express — серверная граница OpenAI и общего бюджета установки. Проекты не хранятся на сервере. Подготовленный пример синтетический. Живой поиск и чтение публичных страниц выполняются сервером при доступной конфигурации и бюджете.

## Потоки данных

```text
Экран → useWorkspace → validated Workspace → Web Locks → localStorage
   ↓ ChatRequest (снимок контекста, requestId)
 src/lib/api → same-origin /api → validation/limits → SQLite reserve
   → semantic planner → optional web_search → bounded public reader
   → permanent mentor protocol + method cards + core context → strict reply + usage
   → SQLite complete/cache → автоматическая память и внутренний контекст → проверка покрытия → добровольный переход
```

`src/App.tsx` соединяет оболочку, маршрут и экраны. `src/features/workspace/` ведёт разговор, предложения, редактор итога, калькуляторы и голос. `src/features/materials/` строит презентацию, профиль, локальную витрину и экспорт из того же состояния. Тематические инструменты используют общий экран разговора. `shared/welcome.ts` экспортирует `getStageWelcome(project: Project, moduleId: ModuleId): { message: string; prompt: string | null }` и формирует стартовую подсказку этапа: при сохранённых фактах предлагает продолжение из контекста, при пустом проекте использует metadata welcome. Стартовые кнопки сразу отправляют запрос. Отправленный текст очищается из draft при создании сообщения, до ожидания ответа; другой неотправленный черновик сохраняется. Завершение ответа больше не изменяет поле ввода. Голос через браузерный SpeechRecognition записывает редактируемый draft, не отправляет его сам.

`shared/types.ts` — контракт Workspace/Project/ModuleState и API. Девять этапов и пять инструментов описаны в `shared/modules.ts`. Чистые `domain`, `validation`, `calculations`, `exports` не зависят от браузера/сервера. Domain определяет доступ, зависимости, stale и объяснимый checklist; оценка не является вероятностью успеха. Изменение фактов/расчётов помечает зависимые итоги устаревшими. Provenance отличает слова пользователя, гипотезы, расчёты, неизвестное и проверенное; модель не получает права сама подтверждать источник.

## Browser persistence и запросы

`WorkspaceProvider` владеет validated updates, `cofounder.workspace.v1`, лимитами20проектов/64МиБ логического JSON и JSON import/export. Большие записи кодируются gzip/base64 без потерь; прежний JSON также читается. `src/state/workspaceStorage.ts` проверяет размер распаковки, UTF-8 и CRC32; запись ограничена2миллионами UTF-16символов, фактическую квоту дополнительно проверяет браузер. Экспорт остаётся полным JSON без сжатия, снимки запросов и история не урезаются. Импорт добавляет копии. Запись под Web Locks повторно сравнивает фактические байты базы с последней сохранённой версией; конфликт вкладок и повреждение блокируют перезапись без подтверждения. Устаревшие ожидающие автосохранения объединяются в последнее. Ошибка квоты не откатывает принятую работу и полученный ответ из памяти. `setProject` возвращает успешность принятия изменения; при отказе валидации новый платный запрос не отправляется. Исходная запись доступна для экспорта; восстановление конфликтующего хранилища требует явного подтверждения. Origin/профиль определяет хранилище, смена порта не переносит данные.

Черновики и исходный payload неуспешного запроса сохраняются. `setProject(updater, projectId?)` направляет ответ в исходный проект при переключении. Retry использует неизменные payload/requestId; импортированные paid snapshots сохраняются, но повторная отправка запрещена (`IMPORTED_REQUEST`), продолжить можно новым сообщением. Внутренний контекст обновляется автоматически; карточки и ручное сохранение не нужны для продолжения. proposedFacts не применяются автоматически. Автоматическая память использует атомы `Project.core` с версиями, исходными цитатами и зависимостями; краткое legacy-резюме не заменяет точные основания. Markdown не допускает raw HTML/опасные URL; экспорт сохраняет источники, stale, оговорки и формулы.

## Сервер и бюджет

`GET /api/health`, `GET /api/status`, `POST /api/chat` обслуживаются `server/app.ts`. `src/lib/api.ts` сначала получает cookie-сессию через status. API проверяет origin, cookie, schema, размер тела1MiB и последовательность ходов одной сессии. Публичные ограничения частоты сообщений, выдачи сессий и глобальной параллельности отключены для локальной демонстрации; положительные программные значения по-прежнему включают эти проверки. Status не раскрывает ключ/баланс. Контекст одного итога ограничен24000 символами; совокупный контекст всё равно обязан помещаться в HTTP limit.

`createApp({provider?,ledger?,config?,admit?})` позволяет тестировать границы через injection; fake-provider недоступен как production настройка. `OpenAIProvider` использует Responses со strict JSON, `store:false`, `maxRetries:0`; ключ/модель только на сервере. Перед генерацией детерминированный поиск по задаче/этапу выбирает до шести полных карточек из воспроизводимого корпуса30 методик, включая M30. Постоянный протокол наставника действует даже без выдачи. `server/knowledge/runtime.json` и manifest содержат собственные карточки и метаданные, без исходного исследовательского архива. Короткий semantic planner выбирает answer/research из любого этапа. Research вызывает hosted `web_search`, затем ограниченный DNS-pinned HTTP-reader. Итог получает серверный каталог фрагментов; URL из текста модели не становится прочитанным источником. Правила/лимиты и дневник подопераций — [ADR0007](adr/0007-research-ledger.md). Векторной БД нет. Браузер запрашивает поток через `Accept: text/event-stream`. Обычный JSON-ответ остаётся доступен, в том числе при возврате результата из ledger. Ошибки/refusal/timeout возвращаются явно.

`server/ledger.ts` — SQLite `node:sqlite`, атомарные reserve/complete/fail, хэш тела вместе с session/requestId, ограниченный кеш ответов и финансовые tombstones. Файл `DATA_DIR/ai-ledger.sqlite` переживает restart. Общий накопительный потолок требует положительного бюджета и ставок модели; неоднозначный расход консервативно списывает резерв. Не удалять ledger и не создавать отдельный лимит ради обхода общего потолка.

С16.11 обычный HTTP-путь использует поэтапный резерв: первый шаг при admission, следующие атомарно перед транспортом. Верхняя стоимость берётся по подготовленному payload конкретного шага, известное завершение освобождает неиспользованный остаток, неизвестный исход удерживает свой резерв. Полный `estimateMaxCost` сохранён для независимых ограничителей проверочных запусков. Расходы остальных запросов учитываются при каждом увеличении резерва; restart сохраняет текущую сумму. Решение и ограничения — [ADR0018](adr/0018-stepwise-budget-reservations.md).

## Поток ответа — 15.11.2026

OpenAI Responses вызывается с `stream:true`; `response.output_text.delta` поступают в `server/streamingMessage.ts`. Strict-схема ставит `message` первым: декодируется только это поле, с обработкой разорванных escape-последовательностей и emoji. Остальной JSON, память, предложения и служебные данные не показываются частями. Полный ответ по-прежнему проходит `validateReply` и проверку usage.

После резервирования бюджета сервер открывает SSE: `start`, `progress` (planning/searching/reading/composing), `text.delta`, затем `complete` либо `error`. Есть heartbeat каждые 15 секунд, `no-store, no-transform` и `X-Accel-Buffering: no`. `complete` отправляется только после записи результата в ledger. Ошибки до открытия потока возвращаются обычным JSON с HTTP-статусом; после открытия — безопасным событием `error`. Отмена/разрыв закрывают запрос через AbortSignal; таймаут и защита от повторной оплаты остаются прежними.

Клиент собирает SSE через ReadableStream/TextDecoder, учитывает разрывы UTF-8 и границ событий, сверяет requestId и ограничивает размеры. EOF без `complete` считается разрывом связи: ручной retry сохраняет тот же payload/requestId и может получить готовый ответ из ledger. Во время генерации текст живёт только в React state и привязан к текущему запросу; память/история/итог меняются после полного ответа. При повторной генерации временный текст занимает место выбранного ответа, при ошибке возвращается прежний. Сброс чата отсекает поздние фрагменты; переход в другой чат не переносит туда поток. Ссылки и действия доступны после завершения проверки ответа. Прокрутка следует за текстом только пока пользователь находится внизу разговора.

Источник контракта провайдера: [Streaming API responses](https://developers.openai.com/api/docs/guides/streaming-responses), [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Проверки: `tests/server/streaming.test.ts`, `tests/server/provider.test.ts`, `tests/workspace/api-stream.test.ts`, `tests/e2e/streaming.spec.ts`. Браузерный транспорт в тестах управляемый; реальное HTTP-flush и повтор из ledger проверяются серверным тестом. Живую проверку отмечать отдельно в PROGRESS.


## Runtime и проверки

Dev Vite3000 проксирует `/api` в Express3001; Vite игнорирует `.autopilot` в watch. Production `npm start` обслуживает только `dist/client` и API, серверный entrypoint `dist/server/index.js`. `APP_ORIGIN` равен origin браузера, в том числе при SSH. Публичный root не содержит `.env`, `.data`, исходники или служебные материалы. Compose/Caddy подготовлены для HTTPS и постоянного ledger, runtime Docker/домен ещё не проверены.

Unit/API проверки используют чистые функции, injected provider и временный ledger. Playwright проверяет UI и mock-контракты на отдельном dev без ключа; HMR-сценарий требует dev. Живые OpenAI/микрофон подтверждаются отдельно, не подменяются mocks: текущие свидетельства в `acceptance.md` и `live-validation.md`. Нерешённые вопросы и договорённости — только `.autopilot/PROGRESS.md`.


## Версии, источники и диагностика первой сборки логики

`Project.core` хранит атомарные решения, ограничения, неизвестное, предложения и отказанные варианты; точные исходные реплики с редакциями; внешние свидетельства. Существующий Workspace version1 расширяется optional-полями. `coreContext` передаёт все версии и `currentEntryRefs`, отдельно от последних40 сообщений и краткого обзора. Prompt разделяет актуальное и историческое; RAG не фильтрует обязательные вводные. `memoryOperations` проверяются и получают доверенный envelope на сервере; `applyAnswer` применяет patch/память/ответ атомарно. Семантическая верность не доказывается совпадением цитаты. [ADR0006](adr/0006-atomic-memory.md) описывает generation, edit, reset, зависимости, миграцию и импорт.

В существующем меню «Посмотреть источники» различаются методики, реплики, унаследованные основания и внешние страницы. Для страницы видны статус чтения, версия, точный фрагмент, даты, ограничения и условия цены. `verified` продолжает означать проверку пользователем. Частичное исследование обозначено также под ответом. Progress отображает только реальные серверные события; затем обычный поток текста. Технические JSON/диагностика не попадают в разговор. JSON сохраняет полное состояние; Markdown включает историю атомов, source refs, исходные реплики, внешние свидетельства/утверждения и зависимости материалов.

Исторические границы UTF-8 bytes первой сборки: HTTP request128KiB, raw model JSON256KiB, полный validated reply512KiB, клиентский JSON/SSE frame1 000 000 и поток2 000 000. Актуальные границы — `shared/transportLimits.ts` и позднейшие решения ниже. Сервер проверяет полный envelope после добавления evidence/diagnostics/knowledge. Входной запрос проверяется до сети; накопленный критический контекст не обрезается, превышение даёт CONTEXT_LIMIT и сохраняет возможность экспорта. С17.11workspace допускает64МиБ логического JSON с компактным хранением; ошибка квоты сохраняет прежнюю запись и текущую работу в памяти.

`scripts/evaluate-bot-core.ts` выполняет reproducible fixtures в явно выбранном режиме. Диагностический DI работает через локальный HTTP `createApp`, тот же конфиг/ledger; не добавляет публичных QA-полей. Default deterministic не вызывает API. Live требует `--live`, сохраняет synthetic inputs, raw structured output, версии, действия, источники и ошибки без ключей/cookies/скрытых рассуждений. Два независимых набора критериев и реальные ограничения — в приёмке (локальный материал), а не в самооценке модели.

## Доверие источникам и диагностический допуск

ADR0020 замыкает исследование в управляемый цикл: независимое nextStep запускает следующую проверку в том же запросе, либо передаёт пользователю конкретный вопрос. До3циклов/360секунд; один цикл до120секунд. Pending/crash deadline согласован с общей задачей. Операции namespaced, usage учитывает все шаги, только итоговый patch применяется к исходной версии памяти. Готовый невалидный ответ оценщика получает одно ограниченное исправление; сетевые и неопределённые исходы не повторяются. Причины остановки видимы. Подробности — [ADR0020](adr/0020-active-research-loop.md).

ADR0019 добавляет восстановление завершённых read последней неудачной исследовательской попытки в той же session/project/module/generation. Сервер передаёт их точные snapshot и `recoveredSourceRefs`; клиент сохраняет первоначальные requestId/даты, не называя восстановление новым чтением. Без отметки другой запрос по-прежнему не может добавить неизвестный исторический read; на сервере любые такие основания сверяются с ledger. Лимит шести страниц относится только к новым чтениям одного исследования, полный каталог ограничен размером envelope. Серверный researchRuntime передаёт реальную доступность поиска и операции оценщику. Подробности — [ADR0019](adr/0019-research-continuation.md).

`server/ledger.ts` сохраняет подоперации planning/search/read/answer и их расходы; дочерний расход учитывается в корне без повторного сложения. Завершённое чтение хранит полный metadata snapshot, включая null-даты. Историческое evidence допускается только в той же защищённой session/project при полном совпадении с сохранённым чтением; сравнение не зависит от порядка object keys, порядок массивов и все значения обязательны. Provider передаёт использованные доверенные исторические основания в итог без объявления нового чтения. Модельный JSON и клиентский URL сами не создают доверенный read.

`shared/coreValidation.ts` предоставляет общий `groundedQuantities` для памяти и серверных утверждений: нормализует допустимые числовые записи, сохраняя ограничения валюты, единицы, периода и происхождения. Проверка цитаты и количества лексическая; она не является универсальным доказательством семантического следования. Неизвестная валюта остаётся неизвестной. Редакционные карточки имеют статус `editorial_draft_not_behaviorally_validated`; воспроизводимость корпуса не означает валидацию поведения модели.

`createApp({admit})` — только программный DI: evaluator проверяет локальный предел дополнительного расхода до `ledger.reserve`. `EVALUATION_LIMIT`409/knownUnspent не создаёт reservation/operation/provider call; runner сохраняет stopped и not_run без retry. Публичных QA-полей или production env-переключателей для обхода нет; общий ledger и потолок установки сохраняются.

Команды проверки структуры не подтверждают live C09/C15 или все сценарии. Текущие статусы, ограничения и итог независимой приёмки фиксируются отдельно в `.autopilot/PROGRESS.md`.

## Проверяемое исправление генерации

Обычный ремонт15.11.2026 добавил ровно один зарезервированный generate-repair для завершённого неверного ответа. Все источники и атомарные guards сохраняются; сеть/неопределённый исход не повторяются. Уточнение16.11 после пользовательского видео: первый SSE preview остаётся видимым при внутренних исправлениях и исследованиях; следующие черновики не передаются, проверенный complete заменяет текст один раз. Новый draft пользователя сохраняется. Конкретные field/rule diagnostics и validation обеих попыток хранятся без raw/секретов в ledger. Полная граница стоимости и ошибки — [ADR0011](adr/0011-bounded-response-repair.md), проверка стабильного preview — разбор записи (локальный материал). Полнота JSON и выбранные методики по-прежнему не доказывают смысловую готовность.

Цикл2 допускает также один отдельно зарезервированный plan-repair после завершённого невалидного JSON/shape/query плана. Максимум5paidchildcalls, без повторов сети/неопределённого исхода и без догадочного выбора из несколькихJSON. Агрегированные safe relatedIssues помогают одной generate-repair исправить независимые нарушения; атомарные и URL guards сохраняются. Детали — [ADR0012](adr/0012-bounded-plan-repair.md).

Цикл3 разделяет основание текста атома: точное маркированное название процитированного same-project read берётся из metadata, тариф — из exact quote. Годовой заголовок не задаёт годовой период цены; произвольные названия и дополнительные числа/единицы проверяются по-прежнему. Проверка видимого ответа ограниченно обнаруживает явное «в прочитанных материалах два тарифа поX», если разные поддержанные claims не дают двух таких оснований. Она направляет ответ в прежнюю ограниченную repair, не подставляет суммы и не является общим семантическим оценщиком. Собственные гипотезы/сценарии и обычное сравнение разных цен не затрагиваются.

Цикл5 сохраняет полную историю citation-only ревизий без ложного stale: существенность сравнивается поkind/key/scope/text/origin/epistemic/acceptance/dependsOn. При следующем действительном изменении проверяются зависимости от всех прежних версий этого атома. Подтверждённая retrieval metadata допускает конечные русские/числовые форматы даты без изменения тарифов иeffective date. URL в прозе распознаются с пунктуацией; точныеURLв реально полученных результатах разрешены как ссылки, но сами не создают прочитанного основания.

Модельный каталог использует локальную точную биекциюsource_N↔(evidenceId,version); только типизированныеexternalrefs преобразуются обратно перед всеми прежнимиguards. Прочитанные тексты,quoteId,даты,URL,числа и статусы не преобразуются. Карта сохраняется вmetadataоперации; вcache/core/UIвыходит canonicalreference. Terminal incomplete/refusal/неопределённый исход не становятся основанием автоматического повтора или частичного применения.

Новые public reads хешируют полный нормализованный HTTP-снимок в пределах4MiB сырого HTML (уточнение16.11.2026 после отказов обычных страниц Asana/Wrike). Модель получает префикс12000 символов через прежний каталог максимум5×500 и, при наличии явного заявления о посредничестве/принадлежности, одну из этих пяти позиций занимает точный фрагмент того же снимка, включая footer за пределом префикса. Дополнительный фрагмент и возможная неполнота каталога явно обозначены; исходные сохранённые источники не мигрируются. Ни бренд, ни домен, ни отсутствие дисклеймера не доказывают operator-owned статус. Контракт — [ADR0015](adr/0015-source-provenance-excerpts.md).

Ссылки модели `подпись (локальный материал)` в message/draft получают точный URL из того же immutable-каталога источников. Явные неправильные URL сохраняют прежний отказ; текст/цены/основания не исправляются. Проекция ограничена по JSON bytes, код и буквальные пользовательские цитаты сохранены, preview не показывает незавершённую активную ссылку. `server/priceUnitBasis.ts` добавляет ограниченную проверку основания тарификации для распознаваемых счётных единиц. Явный знаменатель должен относиться к той же сумме/валюте: число включённых филиалов и операнд калькулятора не делают пакетную сумму ценой за филиал/день. Повтор одинаковой суммы в разных ценовых контекстах не разрешается через случайное подходящее вхождение. Сравнение чисел использует прежнюю точную BigInt-нормализацию; `$` не приравнивается к USD, неизвестность валюты не стирает явную единицу. При недостаточном основании сервер отклоняет ответ с `ungrounded_price_unit_basis`; модель в прежней repair может явно оставить unit=unknown, сохранив сумму, условия и описание лимита/примера. Сервер сам не меняет поля. Это конечная грамматика, не универсальный семантический парсер.

Уточнение 16.11 после повторного пользовательского отказа: запись ценовой карточки `9.99 user/month billed yearly` имеет явную единицу и месячный период при годовой оплате. Непосредственно следующий за суммой `unit/time` поддерживается без обязательного `per` перед unit; лимит `5 users`, соседняя сумма или единица другого тарифа основанием не становятся. В общей проверке чисел поддержаны английские обозначения user-rate и month/monthly/yearly/annually с границами слов, в том числе в русском пересказе. Отсутствующая валюта остаётся unknown. Регрессия и живой результат — повторный разбор (локальный материал).

Два дополнительных конечных контроля проверяют согласованность видимого ответа. `visiblePlanPeriod.ts` связывает явно названный план и ту же сумму/валюту с его структурированным claim: unknown-период не разрешает переносить /мес соседнего плана с одинаковой ценой. Неоднозначные одноимённые планы разных источников не разрешаются догадкой. Буквальные пользовательские цитаты и код остаются данными; это не универсальная проверка всех периодов в прозе.

`inlineArtifactPromise.ts` проверяет конкретные конечные подводки «ниже карточка», «вот она», «привожу здесь» без содержимого после обещания. `artifactDraft` служит внутренним контекстом и сам по себе не выполняет просьбу показать текст в сообщении. На явную просьбу показать в чате проверяются также короткие передачи к отдельному результату. Допустимы самостоятельное содержательное сообщение и отдельный черновик без такого обещания. Неизвестные формулировки вне конечной грамматики не становятся доказанно полезными. Отказ направляет в прежнюю единственную зарезервированную repair с сохранением draft/claims/памяти; сервер не копирует текст автоматически. Реальная переписка пользователя остаётся в частном исходном ledger, тестовые вводные синтетические.

Exact price excerpts сохраняют до240символов соседнего контекста через перенос строки, чтобы назначение опции не отделялось от суммы; предел5×500 и original offsets сохранены. Prompt различает базу/опцию/разовый платёж, а price.unit задаёт основание тарификации, не название плана. Literal guards проверяют основания, но смысловое назначение цены дополнительно проверяется независимым ревью.

Узкий missing_visible_price_qualification проверяет потерю Android/iOS в видимом ценовом сравнении, когда условие уже буквально есть в validated priced claim и его exact read quote. Совпадают сумма, валюта и вид компонента; собственная гипотеза не служит внешней строкой. Если одинаковая ценовая сигнатура имеет конкурирующие платформенные наборы, guard не угадывает источник. Это конечная проверка наблюдённого пропуска, не общий semantic validator; она направляет в прежнюю единственную зарезервированную repair, не подставляет текст и не удаляет claims. Остальные существенные условия и связь неценовых признаков с фрагментом проверяются независимой приёмкой.

Клиентская подготовка различает фактическое превышение1MiB (`CONTEXT_LIMIT`) и несоответствие схеме (`INVALID_REQUEST_CONTEXT`). Раньше обе ветки выдавали ошибочное сообщение о размере. Безопасная копируемая диагностика содержит только bytes разделов, конечные коды и пути схемы/`diagnoseCoreRequest`: без текста, значений, project/request/source IDs. Запрос до сети, исходные данные не меняются. Компактный `RequestNotice` находится в колонке чата; для ошибки подготовки доступны скачивание полного локального JSON и копирование диагностических сведений. Недоступный clipboard даёт поле для ручного копирования.


## Отдельная проверка и методики тем, 16.11.2026

Текущий `server/skills/topic-*/SKILL.md` компилируется в серверный JSON; полный runtime-пакет собирается с каноническими критериями и методиками M01–M30. Планировщик видит каталог и может вызвать `load_topic_skill` один раз для двух дополнительных тем. Это строгое чтение зарегистрированных пакетов, без shell и произвольных путей. Результат инструмента передаётся в продолжение Responses вместе с исходным function_call и reasoning items; затем инструменты отключены. Все версии/операции наблюдаемы в diagnostics/ledger.

После обычных guards выполняется один отдельный evaluator call. Он получает исходные вводные, текущие/исторические версии, прочитанные сервером свидетельства, критерии и видимый результат/предложения памяти, но не author coverage, diagnostics или прошлые оценки. Возвращает покрытие и отдельные проверки процесса/результата. Покрытие ещё проходит literal/user-choice/research guards. Это отдельный вызов той же Sol, с возможными общими ошибками; полноценная экспертная калибровка всех модулей не доказана.

Сервер проставляет модель, время и subjectHash. Проверка хранится в memory.review и вместе с покрытием получает локальный freshness fingerprint; новые вводные, описание, факты, версии, редактирование и reset снимают актуальность. Замечания передаются в следующий ход. Автоматической семантической переписи ответа или повторного вызова судьи нет. Judge имеет отдельный предел до60секунд с запасом3секунды до общей границы запроса; его timeout не обрывает уже готовый ответ. Сбой/невалидный/незавершённый judge сохраняет технически допустимый ответ с review.status=unavailable и удаляет самооценку покрытия. Незавершённый основной ответ по-прежнему не применяется.

Все роли входят в прежнюю общую предварительную резервацию; skill-plan и evaluate имеют отдельные ledger-записи, неизвестный исход оплачивается резервом, retry возвращает сохранённый envelope. Основной ответ и оценщик Sol, поиск Luna; каждая операция записывает фактическую модель. Учтён long-context тариф, консервативный byte bound ограничен физическим пределом Sol 922K input tokens с проверкой usage. Резерв остаётся существенно выше обычного расхода; недостаток резерва может остановить вызовы до номинального исчерпания $15.


16.11.2026: завершение темы и сохраняемый доступ к уже открытым темам — [ADR0017](adr/0017-topic-progression-without-cards.md). При100% достаточно короткой реплики; следующий этап открывается без сохранения карточки.

## Локальная демонстрация — решение16.11.2026

Публичный сайт, домен и HTTPS отменены. Рабочий origin localhost:3000 и серверный ключ сохраняются. Актуальная последовательность — [ADR0022](adr/0022-collect-before-compose.md): Luna-планирование, поиск/чтения и короткие проверки достаточности, один полный ответ Sol, одна независимая оценка Sol. Содержательное замечание оценщика возвращается как честный partial, не запускает очередную полную генерацию. Сохраняются по одному структурному исправлению завершённого невалидного ответа/оценки; короткий план или предварительная проверка могут один раз исправляться на Sol при известном невалидном/incomplete исходе. Сеть/неизвестный usage не повторяются. Deadline задачи15минут, отдельного вызова180секунд; общий cap15, атомарный поэтапный ledger и идемпотентность прежние. Фактические cached input учитываются по известному тарифу модели. Исторические описания полных циклов и полного резерва выше читать с ADR0018/0022.

Размеры UTF-8: запрос1MiB, исходный JSON модели256KiB, проверенный ответ2MiB, клиентский JSON/SSE-кадр4MiB, весь поток8MiB. Диагностика допускает4096операций; полный финансовый след остаётся в ledger. Обычная генерация до6144 output tokens; intent=draft или currentDraft сохраняют настроенный запас16384 по умолчанию/32768максимум. Явные меньшие настройки соблюдаются. Полный критический входной контекст не обрезается; обычный ответ не дублируется в artifactDraft. Сбор источников ограничивают deadline/бюджет, точный повтор query и три проверки без новых прочитанных сведений/улучшения критериев; повтор одного широкого критерия не является остановкой; полный ответ внутри сбора не генерируется. UI сохраняет preview и показывает каждую реальную фазу с прошедшим временем до атомарного итога.

Разбор реального2/4 после оптимизации — проверка ремонта (локальный материал). Каталог справочной статьи теперь учитывает содержательные слова её заголовка ниже приоритета цен/биллинга и выше случайных чисел; точные offsets/hash и предел5×500 сохранены. Успешный поиск с кешированными URL отличается от сбоя оплачиваемого поиска; решения коротких проверок сохраняются в metadata.researchCheck.
