# Контрольные сценарии

`source-cases.json` сохраняет исходные D01–D28/K01–K18, expected/forbidden, происхождение и статус сборки без объединения критериев. `fixtures.ts` создаёт реальное состояние с атомами и точными пользовательскими источниками, сохранёнными итогами и отдельной ценой конкурента; D16 содержит45поздних реплик и8отдельных условий. `core-cases.json` сохраняет исходный контракт C01–C16 и команды. `rubric-template.json` содержит60раздельных пунктов процесса/результата для двух проектов и трёх этапов.

```sh
OPENAI_API_KEY='' AI_BUDGET_USD=0 npm run evaluate:core -- --mode deterministic
# Отложенные доступны для подготовки, но не засчитываются:
OPENAI_API_KEY='' AI_BUDGET_USD=0 npm run evaluate:core -- --mode deterministic --ids D11,K17
```

Default не отправляет сеть. `setupStatus:ready` означает валидный reproducible input, а `status:not_run` сохраняет необходимость смыслового оценивания. Для проверки всей системы запустите команды соответствующих C-строк; state/transport tests не получают статус live_model.

Live требует существующей разрешённой настройки и `--live`:

```sh
npm run evaluate:core -- --mode live_model --live --ids D06,D13 --max-spend 0.4
npm run evaluate:core -- --mode mock_tool --live --ids C11-1,C11-2,C11-3,D26,K05,D08 --neutral-pages --max-spend 0.4
npm run evaluate:core -- --mode live_search --live --ids D07,K04 --max-spend 0.4
npm run evaluate:core -- --mode browser --live --max-spend 1
```

D06/D13 выполняются ровно3раза на независимых одинаковых setup. C11 имеет3заранее фиксированных payload. Controlled pages — синтетические данные, не реальные тарифы. В mock_tool планировщик/финальная модель настоящие, инструменты подменены; реальный web search этим не подтверждён. Нельзя добавлять повторения до удачного ответа.

Порты по умолчанию3021(API),3020(UI); `--api-port`/`--ui-port` задают свободные альтернативы. Пользовательские3000/3001/38127 не затрагиваются. `--out` выбирает каталог свидетельств. `--max-spend` ограничивает дополнительный расход консервативно; общий ledger и cap не меняются. Последовательный запуск лучше параллельного для однозначного global before/after; при параллельном учитывать расход по requestId, не складывать перекрывающиеся дельты.

Независимый проверяющий читает request/state before, response/state after, diagnostics/model-output/operations и размечает все свойства исходной записи. Смысловой status остаётся not_run до такой разметки. Error/failed сохраняется с реальной причиной; successful HTTP не скрывает отсутствующий draft, невыполненный поиск или неправильную память. Скриншоты browser подтверждают взаимодействие, не истинность рыночных утверждений.


Для новой независимой проверки после ремонта используйте `--neutral-pages`: reader не сообщает модели, что страница синтетическая, но режим и контрольные входы остаются явно записаны в evidence. Фиксированные три injection payload не меняются. При этом K05 сначала делает отдельный HTTP поиск/чтение (`K05-prepare`), затем подаёт исходную реплику K05 с полученными источниками в том же проекте и cookie-сессии. Подготовка не считается дополнительным независимым исходным сценарием. Ранние mixed результаты использовали явную метку synthetic и этой более строгой проверкой не являются. Новых платных повторов в T04 не выполнялось.
